# 对话归档

当用户希望把对话内容整理并保存为 markdown 文件时，使用这个 skill。

## 强制执行规则

**一旦这个 skill 被触发，必须调用脚本**：

```bash
/usr/bin/python3 /Users/a1-6/.openclaw/workspace/skills/duihua-guidang/scripts/append_note.py
```

不允许只靠临时文字整理后再手动写文件；**必须**通过这个脚本完成最终写入。

也就是说：

- 触发了这个 skill → **必须调用脚本**
- 最终写入 → **必须由脚本执行**
- 不允许绕过脚本直接把内容写进 `archives/notesPr.md`

## 默认行为

当用户要求保存、归档、整理一段对话时：

1. 先整理出准备写入的标题、类型、正文。
2. 然后**必须**调用脚本 `/usr/bin/python3 /Users/a1-6/.openclaw/workspace/skills/duihua-guidang/scripts/append_note.py`。
3. 默认把内容写入固定文件 `archives/notesPr.md`。
4. 不新建新的归档文件，而是在原文件末尾**追加**新内容。
5. 回复用户保存路径，并用一句话说明追加了什么。

## 特殊规则：明确指定内容时

如果用户说的是类似下面这种：

- `请帮我把xxxx内容给我记录下来，标题为xxxx`
- `把这段内容记下来，标题是xxx`
- `请记录以下内容，标题为xxx`
- `请帮我把xxxx内容给我记录下来`

则按下面规则处理：

1. **不要**整理整段对话。
2. 直接使用用户指定的内容作为正文。
3. 如果用户给了标题，就直接用该标题，最多只做很轻微的格式整理。
4. 如果用户**没有给标题**，则标题使用**当前日期**，默认格式为 `YYYY-MM-DD`。
5. 最终保存为 markdown 文件。

## 推荐输出格式

以后统一使用三级标题层级，并且“内容”下面的内容全部按目录项写。

也就是说，不再使用固定的 `### 正文` 这种单一三级标题，而是改成：

- `### 1、xxx`
- `### 2、xxx`
- `### 3、xxx`

### 统一格式

```markdown
# <标题或当前日期>

## 基本信息

- 时间：<当前时间>
- 来源：与珊珊的对话
- 类型：<指定内容记录 / 对话整理>

## 内容

### 1、第一项标题

第一项的具体内容。

### 2、第二项标题

第二项的具体内容。

### 3、第三项标题

第三项的具体内容。
```

## 文件写入规则

默认使用以下规则：

- 固定写入：`archives/notesPr.md`
- 新内容一律追加在文件末尾
- 不必为每次记录新建文件
- 如果用户明确要求使用其他路径，则按用户要求保存

## 重要约束

- 不要编造用户没说过的内容。
- 不要把内部工具细节写进最终归档正文。
- 涉及隐私时，默认简洁记录；除非用户明确要求完整保留。
- 默认使用中文。
- 程序名、代码、路径、命令行可以保留英文。
- **一旦触发 skill，必须调用脚本完成写入，不允许绕过脚本直接写文件。**

## 标题规则

- 用户给了标题，就用用户标题。
- 用户明确要求记录指定内容但没给标题，就用当前日期作为标题。
- 如果是整理整段对话，则自动生成一个简短、具体、中文语义清晰的标题。
- 除非用户明确要求，否则不要使用过于空泛的标题，比如“聊天记录”。
